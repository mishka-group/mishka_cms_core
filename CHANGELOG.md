# Changelog for MishkaCmsCore 0.0.5

- Names and slugs are made by `mishka_slug` in place of `ash_slug` and `slugify`. An internal name (the `name` of a component, layout, page, site, media item, stylesheet, JS hook, error page and their drafts, which becomes a module, CSS and file name) keeps Latin letters and digits, accents removed (`Café Crème` is `cafe-creme`); other scripts are dropped, not transliterated, and a name with no Latin letter left is refused with "must have Latin letters (a-z) or digits" where `قیمت‌گذاری` used to be saved as `qymtgdhry`. A page named after its title falls back to its path, then `page`. `Changes.InternalName` is the change, and `Languages.slug_locales/1` gives an extension's public slug (`MishkaSlug.Change`'s `locales:`) the site's languages, so a Persian site's slugs stay Persian. The admin's slug preview (`Helpers.follow_slug/4`, `Helpers.slug/3`) makes the slug the save stores
- The dev seeds write a page's Persian or French translation with the name `PageEditions.translate/4` gave it (`localhost-showcase-fa`), so `Seeds.run/2` no longer stops at a Persian name that had no Latin letter to keep
- Every Load more list in the admin ends with one footer on one line, `CardChrome.load_more_footer/1`: the page-size picker (`Show 20 per page`) first, Load More in the middle and the rows shown, `Showing 1–40 of 136`, last. It is laid out by `CardChrome.pagination_row/1`, the row gervaz's own tables draw after 0.0.4 (`Shared.render_pagination_row/1`), and below 640px its parts stack, each centred, with no sideways scroll. The blog's card pages, the drafts sheet, the notification inbox (whose picker read `Per page`) and the activity logs draw it. The activity log puts its count first, now worded like the others (`Showing 1–40 of 10,000+`, over the filter row too), and the last page shown, `Page 4`, last; both come from the table's state, so a Load more reads what it read before. A numbered card list lays its picker, pages and `Page 2 of 7` on the same row. Load More is disabled while a load runs, where the inbox and the activity log hid it
- The card and list pages draw gervaz's Load earlier and its page past the last. A Load more list opened past its first page (`?notifs_page=3`) shows a Load earlier button above its rows, which sends gervaz's `load_earlier` event, and its range label starts at the first row shown (`Showing 41–60 of 136`), ending at the state's `next_offset` when the table keeps one. A page past the last (`?posts_page=999`) reads `Showing 0 of 136` and `No rows on this page` with a `Go to page 1` button, in place of the empty message. `CardChrome.card_scaffold/1` (the blog's posts, tags and collections), `NotificationCard` and `ActivityTimeline` draw them; the Notifications Load More label is capitalised like the other pages. A gervaz that has none of this never shows Load earlier
- An extension adds a tab to the Settings page on the `settings:panels` event. A plugin is handed `%{panels: [], current_user: user}` and answers `%{panels: [...]}` with an `id`, `label`, `icon`, `priority` and a LiveComponent `module:` or a `render:` function; the tab shows only while a plugin answers, and its panel replaces the settings form while it is open
- The Users table has a Confirm email bulk action, behind a confirm prompt, that confirms the email of the users picked. It runs the new `:confirm_pending` action, which holds to the user area and the actor's own site like `:confirm_by_admin` and leaves a user confirmed already as it was. Both announce `auth:account:confirmed` through one change
- `StarterContent.nav_links/1` takes `%{label:, to:}` for a ready path and `%{label:, href:}` for any address, with `target: "_blank"` to open it in a new tab, and a group may carry an `id:`. Every label is escaped, the braces of HEEx included
- A `<p>`, a heading, a `<span>` and the other elements that take phrasing content hold what the HTML standard lists as phrasing content (https://html.spec.whatwg.org/multipage/dom.html#phrasing-content), for a drop and for the code drawer's Apply alike: a `<div>`, a `<ul>`, a `<section>`, a form or a kit card there is refused with "A `<p>` can only hold text and inline elements.", and a `<br>`, `<img>`, `<input>`, `<svg>`, `<select>`, `<del>`, `<button>`, `<a>`, `<label>` or custom element (a name with a hyphen) is taken. A drop used to read every tag outside a short list of inline tags as a block, so an `<img>` or an `<input>` could not be dropped in a `<p>` or a `<label>`. `button` and `label` are held to a form or a text block in a typed document, because the Chelekom kit's tabs, accordion, combobox, radio card, checkbox card and toggle field put a `<div>` in one; so are `summary`, `legend`, `dt` and `figcaption`, which take more than phrasing content in the standard
- `CodeCheck.placement/2` is what the code drawer's Apply asks of typed markup before it replaces the document: it reads the markup into a tree and returns the first element `Containment.misplaced/2` finds misplaced, at its line and column, with the words a refused drop gives. A form (a `<.form>`, or a kit form such as Chelekom's Form Wrapper when `components:` is handed over) or a paragraph or heading inside a `<p>`, a heading or another phrasing-only element is refused with "A `<p>` can only hold text and inline elements.", and a form inside a form with "A form cannot go inside another form". `<p>words <.form>…</.form></p>` used to be saved, and the browser then closed the `<p>` in front of the form, so the canvas disagreed with the Layers and Code views. `HtmlTokenizer.element_positions/1` lists where each element opens
- Placement reads a kit component whose markup opens with another component as the element that one renders: Chelekom's Form Wrapper opens with `<.form>` and is a `<form>`, its Simple Form calls the Form Wrapper and is one too. A kit form dropped in a `<p>`, a heading or an inline tag is refused, so the editor places it beside them; it used to go inside, and the browser closed the paragraph in front of it. Two components that open with each other are let through
- Placement reads the CMS's own function components as the element they render: a `<.form>` is a `<form>`, an `<.input>` the `<div>` around its control, a `<.link>` an `<a>`, a `<.button>` a `<button>` and an `<.icon>` a `<span>`. A form or a field dropped in a `<p>`, a heading or an inline tag is refused, so the editor places it beside them; it used to go inside, and the browser closed the paragraph in front of it
- A `<textarea>`, a `<title>`, a `<script>` and a `<style>` take text and expressions only. An element, a component or a comment dropped or wrapped into one is refused with "A `<textarea>` holds text only.", where it used to be saved and shown on the published page as its own markup
- A `<pre>` keeps the elements in it when a template is read: `<pre><code>…</code></pre>` comes back as a `<code>` an editor can select and style, where it used to be one run of text. Every space and newline stays as it was written
- An HTML comment is read as a comment and the text beside it as text. `<div>a <!-- c --></div>` was written back as `<div><!--a <!-- c --></div>`, the "a" hidden inside the comment, and `<div><!-- c --> b</div>` as `<div><!-- c --> b--></div>`, which showed "b-->" on the page; two comments in a row became one. Each run of text and each comment is now its own node, so the words beside a comment are text an editor selects and edits, a template comes back byte for byte with the spaces and newlines around its comments, a `<pre>` that holds a comment keeps its elements like any other `<pre>`, and an EEx tag written inside a comment is written back as it was, where the comment used to get its `inspect/1` output
- A `<title>` holds its content as one text node, as a `<textarea>` does and as a browser reads it. `<title>Bad <b>title</b> end</title>` was read with a `<b>` inside, which the editor's canvas does not draw in a title, so it showed "Bad  end" while the published page showed the words and the tags as written. An expression in a title is part of that text, written back as it was. A `<script>` and a `<style>` were already read as text
- `Tree.set_text/3` sets a text node's `whitespace?` flag from the new text, as a parse does. Writing a node's own text back returns an equal tree, so an editor's history no longer records "Edited text" for a change that changed nothing, and text emptied to spaces counts as blank
- An element's own CSS is checked by igniter_css's parser, `IgniterCss.validate_block/2`, which reads it as the contents of the rule `css/1` wraps it in. A refusal says where the parser stopped and what it found: "That CSS has an error on line 2, column 22, at `: blue`: Unexpected value or character.". It refuses a `}` that closes the wrapper, also when what follows it parses; a comment, a string, a `(` or a `[` left open, which swallows the wrapper's brace and the rules after it in the stylesheet; a declaration with no colon (`color crimson`, `--brand;`), on which Tailwind refuses the whole stylesheet and the site's CSS build, the draft preview's styles and the canvas's in-browser build stop; a missing `;` (`letter-spacing: 2pxcolor: teal`), which built into a declaration the browser dropped while the box said it was applied; an `@import`, which Tailwind refuses inside a rule; a `//` line, which no browser reads as a comment; and Internet Explorer's `*zoom: 1` hack. A brace, a `;` or a `:` inside a string, a comment, brackets or an escape is text, so `content: "}"`, `url(data:image/png;base64,…)`, `grid-area: a\:b`, `.w-\[10px\]`, `--x: a:b` and a legacy `filter: progid:…` are kept, as are nesting, `@media`, `@supports`, `@container`, `@layer` and `@apply`. The core depends on `igniter_css` `~> 1.1.2`, whose NIF is precompiled
- `TailwindCompiler.author_css/1` finds a stylesheet's `@import`, `@source`, `@plugin`, `@config` and `@reference` with igniter_css's parser (`IgniterCss.list_at_rules/2`) and drops them with `IgniterCss.remove_at_rules/3`, wherever they are: inside `@media`, `@layer` or a rule, and inside `@font-face` or a keyframe, where the regular expression it replaces kept `@font-face { @import "../x.css"; }` whole and Tailwind imported the file. An `@import` in a comment, a string or a `url()` is kept, and a `//` hides nothing, as Tailwind reads it. A stylesheet whose braces do not balance and that holds one of them is left out whole
- `Tree.parse/1` refuses a tag with a `<` in an attribute name, with "a tag is opened inside another tag; close the <.component> with > first" at that attribute's line and column. Phoenix reads a `<` typed inside an opening tag as part of an attribute name, so `<.component compone<nt_name="chelekom-navbar">` was valid HEEx and an Apply in the Code view saved a component with no `name`. A `<` in an attribute's value or expression is kept
- A template with an EEx tag left open, or a closing tag with nothing to close, is refused at its line and column in words: "expected closing '%>' for EEx expression" (the first line of EEx's own message) and "unmatched closing tag </div>". `HtmlTokenizer.build_tokenize/1` raised a `MatchError` and a `FunctionClauseError` on these, so the Code view showed "no match of right hand side value:" or "no function clause matching" with no position. A closing tag directly inside an EEx block (`<%= if @x do %></div><% end %>`) is refused the same way
- A closing tag that does not close the element open where it stands is refused there, naming both: `<div></span></div>` with "</span> does not close <div>" at the `</span>`. `HtmlTokenizer` took any closing tag as the open element's, so the `</span>` closed the `<div>` and the refusal fell on the later `</div>` ("unmatched closing tag </div>"), or a template with an element left open was read with that element closed somewhere else
- A template whose Elixir does not parse is refused at the author's line, in the parser's words: `<%= foo( %>` on line 3 reads "Line 3: missing terminator: )". `CodeCheck.check/1` compiled the template only inside the page's module, behind the confirmation region `LiveViewCompiler.confirmable/3` puts in front of it, so it said "Line 25: token missing on mishka_cms_runtime_page__:25:9:"; it now compiles the template on its own first, as `CodeCheck.template/1` does, and both give a syntax error's description without the generated file name. An EEx block with no `<% end %>` is named as it is written, "<% if true do %> has no <% end %>", where it said "end of template reached without closing tag for <eex_block>"
- A page draft refuses a path another page of its site already has, on its create and its update, with "Page path must be unique within a site." on its `path` field (`Validations.PagePathUnique`). Only `Page`'s identity refused it, when the draft was published, so the editor's Settings said "Saved." and Publish then failed. A draft of the page that has the path keeps it, and another site's pages do not count
- A page's and a page draft's path is stored without a trailing `/` (`Changes.PagePath`, on their creates and updates), as the router serves it: `/about/` is stored as `/about`, and `/` stays `/`. The uniqueness checks compare the stored path, so `/demo-textarea/` was accepted beside `/demo-textarea` and two pages answered one address. `Page`'s creates ask `Validations.PagePathUnique` before the INSERT, so a path a page that is not live already has is refused with "Page path must be unique within a site." on the `path` field instead of a query error in the log; its refusal carries the path as `:answered_at`, so `PageProvision.create/2` still leaves a page whose path arrived after its plan out of a run. A path with no leading `/`, a `?` or a `#` is refused on the `path` field, as before
- The editor's sentences that a component, a layout or an error page shows as well no longer call the document a page: "That form is no longer here.", "There is no form to put it in yet.", "Saving is refused until it is back inside a form.", "Another form here is already called …", "Two forms on one page would mix up each other's answers.", "This value has no code. Write the expression it starts with, like 0.", "This took too long to compile. …", a compiler message's "expected this code to define such a function", "You do not have permission to change author-written Elixir.", and the structures "One wide band, top to bottom." and "A band across the top, then the content.". A sentence about the page a visitor is on keeps the word
- An emptied page, layout, component or error page status saves. `Section.save_fields/3`, which a draft's autosave and a publish both write through, saves markup that is empty or only whitespace as the document a blank create starts with (`PageStarter.blank/1`: the layout's container around `@inner_content` for a layout, the empty container for the rest), and the editor reopens it on the starter. A template is never empty in the database, so an author who deleted everything had every autosave refused and a publish that failed
- The doc of `LiveViewCompiler.shows_messages?/1` says a page with no layout of its own is drawn bare by the host's `RuntimeLive.default_layout/1`, with its content and a flash group, no longer inside `Layouts.app`
- A draft holds the Custom CSS applied to its elements while the editor's stage says Draft: `element_css` (`%{scope => body}`, a blank body for a cleared rule) on `PageDraft`, `LayoutDraft` and `ErrorPageDraft`, beside the markup that carries those scope classes. `Drafts.autosave/8` writes it with the markup when given `element_css:`, `Drafts.save_as/8` takes it from its source, a copy of a draft carries it, and `Drafts.element_owner/1` names the element-CSS row its publish writes into. A rule that would close its element's wrapper is refused, as the editor's box refuses it. It goes when the draft is published or deleted. A host generates the column's migration with `mix ash.codegen`
- Breaking: the draft preview's stylesheet (`/_preview/:resource/:token/css`) is compiled on every open and cached nowhere. `DraftPreviewAssets.css/2` compiles the saved stylesheets, Tailwind over the record's markup and a draft's own Custom CSS laid over its page's element-CSS row as the publish writes it, so a Draft-stage style shows in the new-tab preview. `ensure_css/2`, `refresh_css/2` and the `"css"` key under a preview token in `AssetsState` are gone, `TailwindCompiler.compile_preview/5` takes `rows:` to compile a stylesheet row as a preview holds it, and one record compiles one at a time
- A draft's own `:publish` (the admin's draft list) writes the draft's `element_css` into its document's element-CSS row, as the editor's publish does: laid over the row with `ElementCss.merge/2`, so a rule the draft rewrote replaces the row's, a cleared one goes and the rest stays, written as the publishing user in the publish's transaction (`Drafts.publish_element_css/3`). It used to publish the markup with its scope classes and leave their CSS in the draft, so the live page showed none of it. Pages, layouts and error pages alike
- A stylesheet whose CSS Tailwind will not build is refused on its `content` field, in Tailwind's words, by every write that changes it (`Changes.StylesheetCompiles`, through `TailwindCompiler.verify_css/2`, the check the builder's reusable classes already pass): `.b { color: red;` with "Missing closing } at .b", `@apply rounde-xl` with "Cannot apply unknown utility class `rounde-xl`". The Stylesheets page saved such a row with "Stylesheet updated successfully", and every later build of the site's CSS failed and kept the bundle it had. The check runs when the row is written, not on each keystroke, and before the write's transaction opens, so no database connection is held for the second or two Tailwind takes; the builder's own rows are left to the builder. A Tailwind syntax error is said without the temporary file and line it was found at
- `Page`'s updates ask `Validations.PagePathUnique` before the UPDATE, as its creates do before the INSERT: renaming a page to a path another page of its site has is refused with "Page path must be unique within a site." on the `path` field, where the `unique_path_per_site` index refused it with a query error in the log. The page being updated keeps its own path
- An EEx block left open inside an element is named where it opens, "<% if true do %> has no <% end %>", when the element's closing tag is reached: `<div>` / `<% if true do %>` / `<p>a</p>` / `</div>` said "Line 4, column 1: unmatched closing tag </div>", and now says "Line 2, column 1: <% if true do %> has no <% end %>". A closing tag directly inside a block with no such element open (`<%= if @x do %></div><% end %>`) is still "unmatched closing tag </div>"
- An element's own CSS that holds an `@apply` is built by Tailwind for its site before it is taken (`ElementCss.place/4`, which `put/5` and a draft's `element_css` check go through), and refused in Tailwind's words: `@apply not-a-real-class;` with "Cannot apply unknown utility class `not-a-real-class`", `@apply p-4` with its `;` missing before `color: red;` with "… `color:`", `@apply p-4 !important;` with "… `!important`", and an empty `@apply` with "`@apply` names no utility. Write one after it, like `@apply p-4`.". The parser takes these, and Tailwind failed every stylesheet one was in: the canvas's in-browser build, the draft preview's styles and, on publish, the site's CSS build. The `@apply` is found with `IgniterCss.list_at_rules/2`, and a body with none is not built. `place/3` stays the parser's check alone
- An element's style scope class is never a Tailwind utility. A node id whose hash starts with eight digits was named like `pb-43544908`, which Tailwind built as 43544908 spacing steps of padding-bottom, so the element was millions of pixels tall on the canvas, in the preview and on the live page. `ElementScopes.scope_for/1` names every minted class, the hashed one and a copy's random one: eight digits get a letter for their first, and a class that already holds a letter stays as it was

- `DraftPreviewAssets.ensure_module/2` runs a compile inside the `[:mishka_cms, :runtime, :draft_preview, :compile]` span, with the `module` as the metadata. Its start is emitted from the calling process before it asks for the module's lock
- `CardChrome.range_label/3`, the count over every card list, counts a range only when the page holds rows of the set. A page outside it, such as `?bloggers_page=2` over 14 bloggers or a page below 1, reads "Showing 0 of 14", where it read "Showing 21–14 of 14", a range whose start is past its end. The card's empty label stays for an empty set
- The admin's pages name the icons of the site they are served on, as its public pages do: `MishkaCmsCore.Runtime.AdminSiteIcons`, a plugin on `RootHtml.MetaTags` (the event both hosts' root layouts already fire), appends the `<link rel="icon">` at the site's `site.favicon` and the `<link rel="apple-touch-icon">` at its home-screen icon to the head of every admin page, for the site the host resolved to. A site with neither adds nothing, and a public page keeps the icons its own head names. `Seo.icon_links/1` builds both for a public page's head and the admin's
- A password reset succeeds on ash_authentication 5.0.0-rc.16. rc.16 spends the reset token in a `before_action` hook inside the update's transaction, so `reset_password_with_token` is `require_atomic? false`, as the strategy's own reset action is. Two resets with one link at once are still decided by the token lock. The sign-out, authenticator setup and password-change sign-out tests hold under rc.16: an authenticator setup is confirmed only by the account that started it, and a new password revokes each token once, after the commit, while the device that made the change keeps a new one

The bell hook counts again on it and hands it to the table a page names in `:notification_table`, which reloads its first page; the inbox names its table, so it also shows notifications arriving, read or removed in another tab

# Changelog for MishkaCmsCore 0.0.4

- The release runs on Erlang 29.1.2 and Elixir 1.20.5. The temporary OTP 29.0.5 pin is gone, and every workflow reads `.tool-versions` again

# Changelog for MishkaCmsCore 0.0.3

- Breaking: the visual editor is no longer in the core. It is the new package [mishka_cms_builder](https://github.com/mishka-group/mishka_cms_builder) (`MishkaCmsBuilder`, `MishkaCmsBuilderWeb`), with the editor's pages, canvas, Studio, history, review notes and snippets and their resources. A host that wants the editor adds the package, `MishkaCmsBuilderWeb` to `config :mishka_cms_core, extensions:`, `MishkaCmsBuilder` to its `ash_domains`, `config :mishka_cms_core, builder_strict: config_env() != :prod`, and the package's JavaScript import beside the core's in the admin's `app.js`. The editor's own application starts its processes, so a host drops those children. Without the package the admin keeps the code editor and a create menu opens the form. The editor's tables, addresses and permissions are unchanged
- The core keeps the Authoring layer and answers the editor through plugin seams: `runtime:document:editor_url` (`MishkaCmsCore.Runtime.Authoring.Section.editor_url/3`, the address of the editor, or `nil`), `runtime:provision:snippets` (the snippets an extension's setup writes), `activity:sources` (more sources for the activity log, `MishkaCmsCore.Activity.Behaviours.UnionSource`), a setting definition that covers every key under a prefix (`match: :prefix`), and `ReleaseDraftHistory` plugins on the draft destroy events, which detach a deleted draft's history. With no editor installed each seam answers empty and the core works without it
- Breaking: `MishkaCmsCore.Runtime.PageBuilder` is `MishkaCmsCore.Runtime.Authoring`: the document layer every authored template goes through (the HEEx tree and its edit operations, the checks the compilers and resources run, page forms, and the fields and elements an editor offers), with or without an editor. `PageBuilder.LiveView.HtmlTokenizer` is `Authoring.HtmlTokenizer`
- Breaking: the editor's settings are under its own prefix. `studio.*` is `cms_builder.studio.*`, `builder:preset:<component>` is `cms_builder.preset.<component>`, and `notify.cms_core.page_comment.mentioned` is `notify.cms_builder.page_comment.mentioned` (and `notify.pref.cms_core.page_comment.mentioned` is `notify.pref.cms_builder.page_comment.mentioned`). Values stored under the old keys are no longer read
- Breaking: the editor's own events are named `cms_builder:*`, where they were `cms_core:*`: `cms_builder:page_comment:after_<action>`, `cms_builder:snippet:after_<action>` and the notification type `cms_builder:page_comment:mentioned`. The `builder:*` events of `MishkaCmsCore.Builder.Events` keep their names, so an extension's plugin for the editor needs no change
- Breaking: the core starts `MishkaCmsCore.PubSub` itself, so a host removes its own child for it. `MishkaCmsCore.Supervision.children/1` gives a host the runtime's processes in three groups (`:caches`, `:engine`, `:boot`)
- Breaking: seven functions that nothing called are removed: `Authoring.Binding.preview_count/0`, `Authoring.Containment.phrasing_only_tags/0` and `parent_restricted_tags/0` (`phrasing_only?/1` and `parent_restricted?/1` read the same lists), `MishkaCmsCoreWeb.Templates.CardChrome.modal_footer/1`, `MishkaCmsCore.Install.StarterContent.auth_page_code/1`, and two helpers of the core's own test suite
- The test harness ships in `lib/mishka_cms_core/test/` (`MishkaCmsCore.Test.Boot`, `MishkaCmsCore.DataCase`, `MishkaCmsCore.ConnCase` and their helpers), so an extension's suite boots on it
- The admin's JavaScript hooks ship as ES module sources (`assets/js`, `package.json`) that a host's esbuild imports as `mishka_cms_core`. `mix admin_css` also scans an extension's `assets/js` for the classes its hooks set
- Placement and containment follow HTML. A paragraph, heading or `pre` is a block and no longer goes inside a heading, paragraph or link. A header, footer, main and nav keep to the landmark rules. A kit component is checked as the element its markup opens with. A table's cells, rows and sections go only where a table holds them, so a stray `<td>` is refused instead of stored and published bare. A link is transparent: it takes the content model of its nearest ancestor that is not a link, so a link card fits in a `<div>` and not in a `<p>`, and a link or a button refuses a clickable element at any depth. A page born blank is placed against without its born container, and Start from scratch leaves one bare box the chooser counts as started
- Inspector types are kept. Words typed over a bound property are stored as text, not as an expression that raised on every render. An `any` attribute's type is read from its default, so a list gets the list editor and text for a list or a map is refused with a sentence that says what the property takes. `Inspector.unmet/3` reports a property that holds text where the component takes a list or a map
- A page, a layout or an error page answers when one component raises on a full render (the HTTP render and the connected mount). The component is drawn as a box through `ComponentBoundary`, as the canvas does, where it used to turn the response into a 500 and stop the visitor's LiveView
- Drafts are written and tracked by what publishing does. A publish of a draft writes the draft's settings with the markup (`Drafts.carried/2` says which fields), so an editor can publish its working copy straight to the original and keep them. A draft's fingerprint covers only what publishing writes, so a code save no longer reports the author's own change as someone else's. `Drafts.follow/5` keeps a pending draft in step with a change its own editor made to the original, and `Drafts.get/3` reads a draft by id
- `MishkaCmsCore.EveryPage` reads every row of a read action, not only the first page. The stateful-id and placement checks, the Tailwind compile's layout read, the drafts list and its prune, the extension provision, the starter content and the media move dialog and silent refresh used to take the first page as the whole answer
- A link outside the admin's live_session opens with a page load. This covers a notification in the bell and the inbox, the ways into the visual editor (the + Add button, the Inspector's Visual Editor link and the save of "fill in the form, then open the editor"), so nothing is refused or logged on the way. A document created to be opened in the editor arrives inactive. The core names `phoenix_live_view` itself, at 1.2.10 or later
- The install picker shows each category once, however a kit spells it. Case, spaces, hyphens and underscores are one spelling, and a category beside its own plural is filed under the plural (`UiKitCatalog.file_categories/2`)
- A master's update of a site's layout, component, JS hook or stylesheet is recorded against that site, not as a Global entry missing from the site's activity
- Performance Metrics on the component, page, layout, error page, stylesheet and JS hook cards are real numbers from `RenderMetrics`. A broken CSS or JS bundle build keeps the last good bundle, records the failure and shows it on the stylesheet and JS hook rows
- The gettext templates (`.pot`) and English translations (`.po`) hold every message of the core and of the editor, which uses `MishkaCmsCore.Gettext`. `mix mishka_cms_core.gettext.extensions` reads `../mishka_cms_builder` beside the blog and the document extension
- Dependencies and CI: every dependency is at its latest release, including ash 3.37.2, ash_postgres 2.15.2 and jose 1.11.13 for security advisories. `mix ci` runs `hex.audit` first and `deps.audit`, a `hex-audit` workflow reports to code scanning, Dependabot is on, `ex_dna` holds the clone count at 92 and the Sobelow, Dialyzer and Credo findings are fixed or listed with their reasons
- The split is the plan of [issue #96](https://github.com/mishka-group/mishka_cms_core/issues/96)
