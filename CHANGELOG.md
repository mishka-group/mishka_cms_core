# Changelog for MishkaCmsCore 0.0.3

- Breaking: the visual editor is no longer in the core. It is the new package [mishka_cms_builder](https://github.com/mishka-group/mishka_cms_builder) (`MishkaCmsBuilder`, `MishkaCmsBuilderWeb`), with the editor's pages, canvas, Studio, history, review notes and snippets and their resources. A host that wants the editor adds the package, `MishkaCmsBuilderWeb` to `config :mishka_cms_core, extensions:`, `MishkaCmsBuilder` to its `ash_domains`, `config :mishka_cms_core, builder_strict: config_env() != :prod`, and the package's JavaScript import beside the core's in the admin's `app.js`. The editor's own application starts its processes, so a host drops those children. Without the package the admin keeps the code editor and a create menu opens the form. The editor's tables, addresses and permissions are unchanged
- The core keeps the Authoring layer and answers the editor through plugin seams: `runtime:document:editor_url` (`MishkaCmsCore.Runtime.Authoring.Section.editor_url/3`, the address of the editor, or `nil`), `runtime:provision:snippets` (the snippets an extension's setup writes), `activity:sources` (more sources for the activity log, `MishkaCmsCore.Activity.Behaviours.UnionSource`), a setting definition that covers every key under a prefix (`match: :prefix`), and `ReleaseDraftHistory` plugins on the draft destroy events, which detach a deleted draft's history. With no editor installed each seam answers empty and the core works without it
- Breaking: `MishkaCmsCore.Runtime.PageBuilder` is `MishkaCmsCore.Runtime.Authoring`: the document layer every authored template goes through (the HEEx tree and its edit operations, the checks the compilers and resources run, page forms, and the fields and elements an editor offers), with or without an editor. `PageBuilder.LiveView.HtmlTokenizer` is `Authoring.HtmlTokenizer`
- Breaking: the editor's settings are under its own prefix. `studio.*` is `cms_builder.studio.*`, `builder:preset:<component>` is `cms_builder.preset.<component>`, and `notify.cms_core.page_comment.mentioned` is `notify.cms_builder.page_comment.mentioned` (and `notify.pref.cms_core.page_comment.mentioned` is `notify.pref.cms_builder.page_comment.mentioned`). Values stored under the old keys are no longer read
- Breaking: the editor's own events are named `cms_builder:*`, where they were `cms_core:*`: `cms_builder:page_comment:after_<action>`, `cms_builder:snippet:after_<action>` and the notification type `cms_builder:page_comment:mentioned`. The `builder:*` events of `MishkaCmsCore.Builder.Events` keep their names, so an extension's plugin for the editor needs no change
- Breaking: the core starts `MishkaCmsCore.PubSub` itself, so a host removes its own child for it. `MishkaCmsCore.Supervision.children/1` gives a host the runtime's processes in three groups (`:caches`, `:engine`, `:boot`)
- Breaking: seven functions that nothing called are removed: `Authoring.Binding.preview_count/0`, `Authoring.Containment.phrasing_only_tags/0` and `parent_restricted_tags/0` (`phrasing_only?/1` and `parent_restricted?/1` read the same lists), `MishkaCmsCoreWeb.Templates.CardChrome.modal_footer/1`, `MishkaCmsCore.Install.StarterContent.auth_page_code/1`, and two helpers of the core's own test suite
- The test harness ships in `lib/mishka_cms_core/test/` (`MishkaCmsCore.Test.Boot`, `MishkaCmsCore.DataCase`, `MishkaCmsCore.ConnCase` and their helpers), so an extension's suite boots on it
- The admin's JavaScript hooks ship as ES module sources (`assets/js`, `package.json`) that a host's esbuild imports as `mishka_cms_core`. `mix admin_css` also scans an extension's `assets/js` for the classes its hooks set
- Placement and containment follow HTML. A paragraph, heading or `pre` is a block and no longer goes inside a heading, paragraph or link. A header, footer, main and nav keep to the landmark rules. A kit component is checked as the element its markup opens with. A table's cells, rows and sections go only where a table holds them, so a stray `<td>` is refused instead of stored and published bare. A link is transparent: it takes the content model of its nearest ancestor that is not a link, so a link card fits in a `<div>` and not in a `<p>`, and a link or a button refuses a clickable element at any depth. A page born blank is placed against without its born container, and Start from scratch leaves one bare box the chooser counts as started
- Inspector types are kept. Words typed over a bound property are stored as text, not as an expression that raised on every render. An `any` attribute's type is read from its default, so a list gets the list editor and text for a list or a map is refused with a sentence that says what the property takes. `Inspector.unmet/3` reports a property that holds text where the component takes a list or a map
- A page, a layout or an error page answers when one component raises on a full render (the HTTP render and the connected mount). The component is drawn as a box through `ComponentBoundary`, as the canvas does, where it used to turn the response into a 500 and stop the visitor's LiveView
- Drafts are written and tracked by what publishing does. A publish of a draft writes the draft's settings with the markup (`Drafts.carried/2` says which fields), so an editor can publish its working copy straight to the original and keep them. A draft's fingerprint covers only what publishing writes, so a code save no longer reports the author's own change as someone else's. `Drafts.follow/5` keeps a pending draft in step with a change its own editor made to the original, and `Drafts.get/3` reads a draft by id
- `MishkaCmsCore.EveryPage` reads every row of a read action, not only the first page. The stateful-id and placement checks, the Tailwind compile's layout read, the drafts list and its prune, the extension provision, the starter content and the media move dialog and silent refresh used to take the first page as the whole answer
- A link outside the admin's live_session opens with a page load. This covers a notification in the bell and the inbox, the ways into the visual editor (the + Add button, the Inspector's Visual Editor link and the save of "fill in the form, then open the editor"), so nothing is refused or logged on the way. A document created to be opened in the editor arrives inactive. The core names `phoenix_live_view` itself, at 1.2.10 or later
- The install picker shows each category once, however a kit spells it. Case, spaces, hyphens and underscores are one spelling, and a category beside its own plural is filed under the plural (`UiKitCatalog.file_categories/2`)
- A master's update of a site's layout, component, JS hook or stylesheet is recorded against that site, not as a Global entry missing from the site's activity
- Performance Metrics on the component, page, layout, error page, stylesheet and JS hook cards are real numbers from `RenderMetrics`. A broken CSS or JS bundle build keeps the last good bundle, records the failure and shows it on the stylesheet and JS hook rows
- The gettext templates (`.pot`) and English translations (`.po`) hold every message of the core and of the editor, which uses `MishkaCmsCore.Gettext`. `mix mishka_cms_core.gettext.extensions` reads `../mishka_cms_builder` beside the blog and the document extension
- Dependencies and CI: every dependency is at its latest release, including ash 3.37.2, ash_postgres 2.15.2 and jose 1.11.13 for security advisories. `mix ci` runs `hex.audit` first and `deps.audit`, a `hex-audit` workflow reports to code scanning, Dependabot is on, `ex_dna` holds the clone count at 92 and the Sobelow, Dialyzer and Credo findings are fixed or listed with their reasons
- The split is the plan of [issue #96](https://github.com/mishka-group/mishka_cms_core/issues/96)
- Release order: installer and gervaz, then mishka_cms_core 0.0.3, then mishka_cms_builder 0.0.1-alpha.1, then hosts and extensions
